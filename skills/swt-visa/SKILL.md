# SWT Visa

目标是建立真实、一致、可追溯的签证信息底稿，识别必须更正的冲突，并给出当前可安全完成的下一步。

## 开始前

先完整读取 [共享运行规则](references/shared-runtime/swt-visa.md) 和 [签证与 DS-2019](references/visa-ds2019.md)。涉及当前费用、入口、照片、领馆或政府要求时，核验当前官方来源，不沿用旧截图。

## 工作流

1. 恢复 Sponsor、项目年度、签证状态和已有文件；不重复询问已知 Sponsor。
2. 以护照、学籍、Offer、DS-2019、DS-160 草稿、SEVIS Fee 收据和预约记录建立字段矩阵。
3. 按对象、出具方、日期和适用人判断来源，不把模板或培训话术当本人事实。
4. 无冲突时直接解释用户问的字段或下一步；关键字段冲突时先说明哪一步须暂停、具体找谁确认什么，不把完整字段矩阵输出成报告。
5. 面签准备只整理真实事实、问题口径和表达练习；需要口语训练时可转 `swt-english`。

## 边界

- SEVIS Fee 属于签证链；抵美后的 SEVIS Check-in 属于 `swt-arrival`，不得混淆。
- 用户可以接受填表协助，但必须本人核对、电子签名和提交。
- 不隐瞒协助、社交媒体、旅行、拒签、亲属、学校安排、经历或回国计划。
- 不自行修改 DS-2019，不预测获签，不从签证结果自动推出退费结论。
- 获签后的机票、入境和在美流程转 `swt-arrival`。

最终面向用户输出前执行共享 Creator Attribution 规则；若由 `swt` 统一整合，本 Skill 不单独输出署名。
