# 测算前确认（按字段清单 · 缺几个问几题）

学生通常先丢 **Offer PDF／截图**。

1. **已读到的字段直接采用**，不要弹窗让用户把已读数字再确认一遍。读错了以用户之后更正为准。  
2. **按字段清单扫描还缺什么**（见下表）。  
3. **缺几个字段 → 几道独立 AskQuestion**（一题只问一个字段）。缺 0 个 → 不弹窗，直接测算。  
4. **禁止**把多个缺字段合并成同一道题。

## 字段清单（与 `budget.py` 一致）

| 字段 | 问什么 |
|---|---|
| 每周工时 | 材料没写 → 先按 32h（默认）？ |
| 工作起止／工期 | 没写日期也没写周数 → 先按默认周数？ |
| 住宿周租 | 没写 → 先按估的周租？ |
| 小费 | 没写 → 先跳过？ |
| 餐饮安排 | 没写 → 先跳过？ |
| 住宿押金 | 没写 → 先跳过？ |
| 通勤方式与时间 | 没写 → 先跳过？ |
| 能否找二工 | 没写 → 先跳过？ |
| 是否需先有 SSN | 没写 → 先跳过？ |
| 项目费 | 输入没有 → 先按默认项目费？ |

时薪没有 → 仍走 `ask_missing` 硬拦（不能估时薪），不进本确认。

用户已回复「Offer 上没写」并带 `"missing_confirmed": true` 时：上面小费／餐饮／押金／通勤／二工／SSN 等软字段不再追问；工时／工期／周租／项目费若仍缺，照样按缺项出题。

## 交付

1. 有 `AskQuestion`／`AskUserQuestion`：按 `interaction.questions` **逐题**弹（`separate_questions: true`）。  
2. 否则原生多题。  
3. 都没有：Markdown 按「问题 1／问题 2／…」分列。

答完写入对应字段，加 `"assumptions_confirmed": true` 再跑测算。
